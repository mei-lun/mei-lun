23种设计模式

对接口编程而不是对实现编程。

优先使用对象组合而不是继承。

1.创建型模式

创建型设计模式提供隐藏创建逻辑的方式，而不是直接用new运算符直接创建实例

  1. 工厂模式：实体工厂
  2. 抽象工厂模式：创建工厂的工厂，解决了工厂的接口选择问题
  3. 单例模式：可以直接访问，不需要实例化对象。避免一个全局使用的类频繁的创建和销毁。生产唯一的id。懒汉式：第一次调用的时候才会初始化，避免浪费内存。这个类的性能对应用程序不是很关键，该方法是用的不是很频繁。饿汉式：类加载的时候就初始化，浪费内存。
  4. 建造者模式：类似背包，把不同的实体和类打包在一起
  5. 原型模式：副本的创建，玩家每次进行不同关卡的时候会对副本地图进行创建和销毁，有一个原型模式就可以避免

2.结构型模式

  1. 适配器模式：两个接口的内容不一样，比如getId和getPid和getPlayerId
  2. 桥接模式：将抽象部分和实现部分分离，有点类似C++的多继承，实现的系统有多个角度的分类，每一种角度都有可能会变化。扩展能力优秀。
  3. 过滤器模式：（标准模式）？：用基类创建所有的对象，然后通过实现类的规则过滤出我们符合条件的类。
  4. 组合模式：类似工程里的组建模式，之前的玩家名和帮派名排行榜应该使用组合模式
  5. 装饰器模式：在不影响原本类的情况下再封装这个类，然后再在想要的地方附带上新加的功能

  1. 外观模式：在类和类的调用中间再包一层，然后通过给一个特定的接口和函数去调用，在外部看起来是一样的。降低访问复杂系统的内部子系统时的复杂度，简化客户端之间的接口。
  2. 享元模式：把所有类共有的部分提取出来，然后只创建一份。在查找的时候先从缓存里找，如果缓存里没有则把新的数据加入缓存。减少数据的开销。
  3. 代理模式：如果想在访问一个类时做一些控制。可以在中间再加一层，通过中间这一层进行控制。

3.行为模式

  1. 责任链模式：中间套了一层，客户端只需要传递对应的参数，然后消息由这个中间层来转发，决定调用什么函数。
  2. 命令模式：将一个请求封装成一个对象，从而使您可以用不同的请求对客户进行参数化。将”行为请求者”与”行为实现者”解耦？将一组行为抽象为对象，可以实现二者之间的松耦。把请求包起来，创建一个对象去执行命令。
  3. 解释器模式：创建多个对象，然后在对象之间设置规则，通过输入来判定输入是否符合设定的规则
  4. 迭代器模式：迭代器就和C++的STL一样，封装起来，vector，map，list都可以直接用迭代器访问。
  5. 中介者模式：类和类之前加一层中间层，让一对多的关系变成一对一的关系。
  6. 备忘录模式：通过一个备忘录类专门存储对象状态，1、需要保存/恢复数据的相关状态场景。 2、提供一个可回滚的操作。
  7. 观察者模式：定义对象间的一种一对多的依赖关系，当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并被自动更新。一个对象（目标对象）的状态发生改变，所有的依赖对象（观察者对象）都将得到通知，进行广播通知。
  8. 状态模式：代码中包含大量与对象状态有关的条件语句。将各种具体的状态类抽象出来。1、行为随状态改变而改变的场景。 2、条件、分支语句的代替者。
  9. 空对象模式：在空对象模式（Null Object Pattern）中，一个空对象取代 NULL 对象实例的检查。Null 对象不是检查空值，而是反应一个不做任何动作的关系。这样的 Null 对象也可以在数据不可用的时候提供默认的行为。
  10. 策略模式：在有多种算法相似的情况下，使用 if…else 所带来的复杂和难以维护。一个系统有许多许多类，而区分它们的只是他们直接的行为。
  11. 模板模式：C++STL的模板
  12. 访问者模式：把我需要的方法传进类里，让类里面进行操作。将数据与操作分离。
