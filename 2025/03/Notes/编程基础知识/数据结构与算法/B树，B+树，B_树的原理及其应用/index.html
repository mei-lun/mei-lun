B树，B+树，B*树的原理及其应用

B树

基本概念：每个节点中都保存数据

  • 每个节点存储键值和数据（数据可能分布在所有节点）
  • 所有叶子节点在同一层
  • 节点填充因子较高（至少一半满）

应用：

  • 嵌入式数据库（如SQLite）：数据直接存储在节点中，适合小规模快速查询
  • 文件系统元数据管理（如NTFS、ReiserFS）：目录结构快速定位
  • 内存受限场景：减少磁盘寻道次数，例如早期MongoDB（3.0前）的默认索引结构
  • 实时系统：查询和更新延迟稳定，无叶子节点遍历开销

B+树

基本概念：子节点中只保存索引，所有的数据都保存在叶子节点中，并且把叶子节点用指针连接起来

  • 数据仅存在叶子节点，内部节点仅存键值
  • 叶子节点通过指针链表连接
  • 节点填充因子更高（通常2/3满）

应用：

  • 关系型数据库索引（MySQL InnoDB、PostgreSQL）：范围查询高效
  • 日志结构存储系统（LSM-Tree的SSTable索引）
  • 时间序列数据库（如InfluxDB）：按时间戳范围快速检索
  • 文件系统（如Ext4）：大文件连续块地址管理

B*树

基本概念：子节点只保存索引，所有数据保存在叶子节点中，把所有子节点还有叶子节点用指针连接起来

  • 非叶子节点增加兄弟指针
  • 节点填充因子更高（通常2/3满）
  • 分裂策略优化：节点满时先尝试向兄弟节点转移数据

应用：

  • 高并发文件系统（如ZFS、Btrfs）：减少节点分裂频率
  • 分布式存储系统：优化多节点负载均衡
  • 版本控制系统（如Git底层对象存储）：高效处理大量小文件
  • 实时数据分析系统：高写入吞吐场景

特点及其应用场景：

1. 需要范围查询 → 选B+树（如数据库索引）

2. 内存有限+随机访问 → 选B树（如嵌入式系统）

3. 高并发写入+空间敏感 → 选B*树（如分布式文件系统）

4. 混合负载场景 → B+树变种（如Google的Bw-tree）

实际系统中常会结合使用，例如：

  • MySQL InnoDB：B+树主键索引 + B树辅助索引
  • MongoDB WiredTiger：B树索引 + LSM-Tree日志结构合并
特性 B树 B+树 B*树
数据存储位置 所有节点 仅叶子节点 仅叶子节点
叶子节点链接 无 双向/单向链表 双向/单向链表
节点填充率 ~50% ~66% ~75%
分裂频率 较高 中等 较低
适用场景 随机读写 范围查询 高并发写入
